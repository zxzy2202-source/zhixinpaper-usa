## Grouping method

Two identifiers are intentionally retained:

- `IF-*` is an implementation family: the owning JSX/component branch. Similar copied JSX in different files is never merged. Conditional branches in one file are split when their first viewport differs.
- `VG-*` is a visual baseline group. The fixed inventory uses one visual group per URL. This conservative boundary is required because route data can change title/description wrapping, CTA labels/count, metadata rows, aside height, media, pilot CSS, or the content immediately adjacent to the banner. Pixel-equivalence across distinct URLs was not established.

Consequently there are **97 visual groups and 97 representative routes**. Each group’s representative is its sole URL; that is representative by identity and preserves every unproven text-height/data state.

Public state conventions: `/contact`, `/samples`, and `/quote` use their initial unsubmitted branches; `/blog` uses initial category `ALL`; blog details document both DB-first and static-fallback states.

## Shared HeroBanner contract

`src/components/ui/HeroBanner.tsx:14-24` defines `title`, optional description/eyebrow/breadcrumbs/actions/aside/media, variant, and class name. At `:26-42`, the default variant is `standard`, only `actions.slice(0, 2)` renders, `standard` is light, and `media`/`overview` are dark. An aside or media enables the two-column content grid. At `:45-59`, media is an absolute full-banner layer with a fixed dark overlay; a dark banner without media gets the radial treatment. The title/copy and CTA rendering are at `:77-113`; aside output is at `:115`.

Variant notation below:

- `HB-standard`: shared light banner.
- `HB-media`: shared dark banner; “no media” means the media variant was selected without a `media` prop and therefore uses the radial dark background.
- `HB-overview`: shared dark overview banner, with aside support.
- `Custom`: JSX owned by the named page/client/delegated component.

## Runtime database-blog variables

`src/app/blog/[slug]/BlogPostClient.tsx` gives a found database post precedence over `BLOG_POSTS`; static data is fallback. The DB first viewport varies with `title`, `excerpt`, `category`, `readTime`, `publishedAt`, `createdAt`, and `tags`. `coverImage` conditionally creates the media block immediately after the hero. Therefore ordinary fixed blog URLs use IF-52 when a published DB row with the slug exists and IF-53 otherwise; `/blog/what-is-thermal-paper` uses the pilot states IF-55 when a matching DB row exists and IF-54 otherwise. New published DB-only slugs can also extend the production sitemap beyond 97. Sitemap discovery uses DB `slug`, `publishedAt`, `updatedAt`, and `createdAt` with `status = "published"` (`src/app/sitemap.ts:118-143`).

## Runtime image slots

`src/components/ui/SlotImage.tsx:31-48` awaits `resolveSlot(slotKey)` and renders the resolved URL/alt. `src/lib/imageSlotResolver.ts:38-68` loads all `imageSlots` joined to `mediaFiles`; a valid DB binding wins. At `:76-100`, absent bindings, deleted media, or DB failure use the registry fallback; an unknown key safely falls back to `/images/hero-bg.jpg`. Normal cache TTL is 60 seconds (`:35`); DB failure is cached for 5 seconds (`:64-68`).
